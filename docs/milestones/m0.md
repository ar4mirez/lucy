# m0: foundation

## Goal

Lay the foundation every later milestone stands on, before lucy runs any real work: one typed API, an
event store, a deterministic policy engine, the ai-sdlc spec model, a simulation harness, the
conformance corpus harness with corpus v1, signed releases installed through mise, and lucy's own
security baseline. 37-57 PRs, about 0.9-3.1B processed tokens.

Notes per slice:

- **1, skeleton.** No product code beyond `lucy --version` and `--help`. The doc rules are a Go test
  (`internal/doccheck`), so CI enforces them from the first commit.
- **2, releases.** Mirrors berth's signed pipeline ([D7](../decisions/D7-distribution-mise.md));
  runbooks: [release](../runbooks/release.md), [verify a release](../runbooks/verify-release.md).
  The first tag is cut by the owner, not by an agent.
- **3, event store.** Pure-Go SQLite (`modernc.org/sqlite`); the append-only log is the source of
  truth and state is projections of it; events and state change in one transaction; consumer
  cursors with generation-bound acks replace the old supervisor's wake files. Package `internal/eventstore`;
  operations in the [database runbook](../runbooks/database.md). The audit hash chain is slice 6: a
  projector over this log.
- **4, API.** Restricted JSON-RPC 2.0 over HTTP on the daemon's unix socket, with a generated
  OpenRPC schema ([D10](../decisions/D10-api-json-rpc.md)). Packages `internal/api` (method table,
  wire format, errors, schema), `internal/api/client`, `internal/server` and `internal/daemon`;
  operations in the [daemon runbook](../runbooks/daemon.md). No network listener exists:
  remote HTTPS with device pairing, scoped credentials and TLS lands in m1 (LUCY-VIEW-006).
- **4-5, API and policy.** Every API command passes the policy engine; models only request.
- **5, policy.** A pure, deterministic Go engine (`internal/policy`): typed requests (actor, kind,
  target org, project and resource, the source of every input), facts the daemon gathers, a fixed
  rule order ending in default deny, and decisions recorded as `policy.decision` events before
  they are returned (`policy.evaluate`, `policy.decisions`). No policy-language dependency: the
  rules are Go, and the spec model feeds them data (AutonomyPolicy postures in m1). The path guard (`internal/pathguard`)
  is the primitive LUCY-SEC-005 wires into every delete lucy makes in m1.
- **6, spec model.** The m0 part of adopting the ai-sdlc spec ([D3b](../decisions/D3b-ai-sdlc-spec.md),
  [D11](../decisions/D11-spec-loading.md)): the resource envelope with a required namespace (the
  airspace), the spec/status split (files hold spec, the event store holds status as
  Conditions), validation on load against the vendored schemas, lucy's own kinds as schema stubs,
  and the audit hash chain. Packages `internal/spec`, `internal/jcs` and `internal/audit`; commands
  `lucy config validate|status` and `lucy audit verify`. Converge loops (LUCY-SPEC-008) and
  modelling QualityGate and AutonomyPolicy beyond schema validation (LUCY-SPEC-010) moved to m1.
  The companion docs (`policy.md`, `autonomy.md`, `agents.md`, `adapters.md`, `metrics.md`) were
  read for this slice; only `metrics.md`'s audit fields bear on it (the actor type rides in each
  entry's `details`).
- **7, simulation.** The Tower's flight state machine (`internal/tower`) and the harness that
  drives it (`internal/sim`). The machine reaches the world only through three seams the m1
  adapters implement: a Pilot `Runtime` (start, poll, answer, stop), a `Forge` (read a pull
  request; merge only the cleared head) and a `Clock`. The fakes script Pilots (work, ask, give
  up, hang, crash, open a pull request with passing, failing or flaky checks) and the forge
  (required checks, conflicts, a push or base move by someone else, a lost merge reply) on
  virtual time, with one seeded generator. Fault hooks for the m1 chaos suite (LUCY-SIM-003):
  `World.Restart` reopens the store mid-flight, `Runtime.Kill` and the `Crash` step lose a
  session, `RunOptions.BeforeStep` injects either at any step.
- **8, corpus.** TODO(LUCY-CORP-002): mine the old supervisor's safety rules and its homes' status logs and
  incidents (the four in [PRODUCT.md](../../PRODUCT.md)) into executable scenarios.

## Out of scope

Running any real task, berth, the credential gateway, harness adapters, the validation pipeline and
every viewer: all m1. Homebrew: m3.

## Exit tests

1. Signed releases install with `mise use -g github:ar4mirez/lucy` on Linux and macOS, and mise
   verifies their attestations (LUCY-REL-001 to LUCY-REL-004).
2. The vendored schemas validate the spec's own examples (LUCY-SPEC-004, LUCY-SPEC-011).
3. The policy engine refuses every privileged action in the simulation suite unless a rule allows it
   (LUCY-POL-001, LUCY-SIM-002).
4. Corpus v1 runs; red is expected, since nothing is implemented yet (LUCY-CORP-001, LUCY-CORP-002).
5. lucy's CI blocks on its own vulnerability and dependency scans (LUCY-SEC-002).
6. The STRIDE ADR is in (LUCY-SEC-003).
7. The doc-rules test is green on Linux and macOS (LUCY-REPO-002 to LUCY-REPO-005, LUCY-REPO-007).
