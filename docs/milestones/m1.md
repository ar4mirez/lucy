# m1: ar4mirez end to end

## Goal

lucy runs one org, ar4mirez, end to end ([D2 revised](../decisions/D2-first-milestone.md)): first in
shadow mode next to firstmate, then taking over one task class at a time with a one-command rollback.
lucy's own lean validation pipeline lands here, because this is where lucy first runs real work
([D4](../decisions/D4-lean-validation.md)). The doctor checks fold in. 145-215 PRs, about 3.6-11.8B.

## Scope (in build order; each step leaves ar4mirez working)

1. Runner protocol, local and in-container runners (LUCY-RUN-001).
2. Structured-protocol Claude Code adapter and the harness churn guard (LUCY-RUN-002, LUCY-RUN-003).
3. berth as the Sandbox binding; runtime seam (LUCY-SBX-001 to LUCY-SBX-003, LUCY-SPEC-016).
4. Credential gateway, vault and capability tokens (LUCY-CRED-001 to LUCY-CRED-005).
5. Session ownership, reattach and fencing; restarts that keep runners alive (LUCY-RUN-004,
   LUCY-RUN-005, LUCY-OPS-005).
6. Worktree pool, per-task TMPDIR, synthetic HOME, delete guard (LUCY-RUN-006, LUCY-RUN-007,
   LUCY-SEC-005).
7. Task lifecycle on spec resources: readiness, decisions, pipelines, roles, conformance
   (LUCY-SPEC-012 to LUCY-SPEC-015, LUCY-SPEC-017).
8. Account convergence and hashed skills (LUCY-RUN-008, LUCY-RUN-009).
9. Deterministic-first supervision and cost accounting (LUCY-RUN-010, LUCY-RUN-011).
10. Shadow mode (LUCY-RUN-012, first half).
11. Lean validation pipeline, signed proofs and the merge function (LUCY-VAL-001 to LUCY-VAL-007,
    LUCY-VAL-009, LUCY-VAL-010, LUCY-SEC-008).
12. Validation benchmark with a second model family (LUCY-VAL-008).
13. Takeover by task class and `lucy handback` (LUCY-RUN-012, second half).
14. Viewers and remote control (LUCY-VIEW-001 to LUCY-VIEW-007, LUCY-SEC-006). m0 ships only the
    unix socket, so this adds the HTTPS transport for the one API: the same `/rpc/v1` handler,
    loopback and tailnet binds, TLS, and paired-device credentials checked per call.
15. `lucy setup`, `lucy doctor`, backups and the host baseline (LUCY-OPS-001 to LUCY-OPS-003,
    LUCY-SEC-007).
16. Observability, the chaos suite and corpus growth (LUCY-OPS-004, LUCY-SIM-003, LUCY-CORP-003).

## Out of scope

Other orgs, seat pools and quota failover, offboarding, the knowledge model, the importer (m2). The
full dashboard, passkeys and the Claude Code plugin (m3).

## Exit tests

1. Shadow mode on ar4mirez shows lucy's proposals matching firstmate's actions for each task class it
   takes over (LUCY-RUN-012).
2. 20 consecutive ar4mirez tasks land through lucy, validated by its own pipeline inside berth
   containers, with no lost work, no duplicate sessions and no token inside any container
   (LUCY-SBX-001, LUCY-RUN-004, LUCY-CRED-005, LUCY-VAL-005).
3. The corpus is green for ar4mirez's flows; the chaos suite passes, kill-chain scenarios included
   (LUCY-CORP-003, LUCY-SIM-003).
4. Cost per merged PR is at most firstmate's (LUCY-RUN-011).
5. The pipeline benchmark shows the same blocking catches as no-mistakes on the replayed PRs
   (LUCY-VAL-008).
6. Every session survives killing all its viewers and restarting the daemon (LUCY-RUN-005).
7. Angel answers a decision and steers a worker from his phone and from Claude desktop on another
   machine (LUCY-VIEW-005, LUCY-VIEW-006).
8. `lucy doctor` is green after `lucy setup` on a clean machine (LUCY-OPS-001, LUCY-OPS-002).
9. Core conformance and the audit-chain fixture pass (LUCY-SPEC-017).
10. `lucy handback` returns a task class to firstmate in one command (LUCY-RUN-012).
11. The STRIDE rows marked m1 are checked.
