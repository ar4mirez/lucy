# m1: ar4mirez end to end

## Goal

lucy runs one org, ar4mirez, end to end ([D2 revised](../decisions/D2-first-milestone.md)): first in
shadow mode next to the supervisor it replaces, then taking over one task class at a time with a one-command rollback.
lucy's own lean validation pipeline lands here, because this is where lucy first runs real work
([D4](../decisions/D4-lean-validation.md)). The `lucy preflight` checks fold in. 145-215 PRs, about 3.6-11.8B.

## Exit tests

1. Shadow mode on ar4mirez shows lucy's proposals matching the old supervisor's actions for each task class it
   takes over (LUCY-RUN-012).
2. 20 consecutive ar4mirez tasks land through lucy, validated by its own pipeline inside berth
   containers, with no lost work, no duplicate sessions and no token inside any container
   (LUCY-SBX-001, LUCY-RUN-004, LUCY-CRED-005, LUCY-VAL-005).
3. The corpus is green for ar4mirez's flows; the chaos suite passes, kill-chain scenarios included
   (LUCY-CORP-003, LUCY-SIM-003).
4. Cost per merged PR is at most the old supervisor's (LUCY-RUN-011).
5. The pipeline benchmark shows the same blocking catches as the validation daemon it replaces on the
   replayed PRs
   (LUCY-VAL-008).
6. Every session survives killing all its viewers and restarting the daemon (LUCY-RUN-005).
7. The owner answers a decision and steers a worker from a phone and from Claude desktop on another
   machine (LUCY-VIEW-005, LUCY-VIEW-006).
8. `lucy preflight --check` is green after `lucy preflight` on a clean machine (LUCY-OPS-001, LUCY-OPS-002).
9. Core conformance and the audit-chain fixture pass (LUCY-SPEC-017).
10. `lucy handback` returns a task class to the old supervisor in one command (LUCY-RUN-012).
11. The STRIDE rows marked m1 are checked.
